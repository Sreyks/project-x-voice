# Project X — голосовой чат с собственным распознаванием речи

Веб-чат в браузере: говоришь в микрофон — сервер сам превращает голос в текст (без сторонних облачных API распознавания) и может ответить через ИИ. Два взаимозаменяемых движка распознавания в одном проекте — под видеокарту и без неё.

## История

Это вторая, «серьёзная» попытка сделать голосовой ввод (первая, попроще, — соседний проект `06-Rasp-rechi-Golos`). Здесь цель была не «взять готовое приложение», а самому поднять модель распознавания речи и понять, как она работает внутри — от загрузки весов до инференса на GPU.

По пути перепробовано несколько движков: браузерный Web Speech API (мгновенно, но неточно и без выбора языка), Whisper large-v3 на CPU (точно, но 10+ секунд на фразу — слишком медленно для чата), его turbo-версия (быстрее, но всё равно вязко). В итоге прижились два рабочих варианта, которые остались в проекте как осознанный выбор, а не промежуточные черновики: **heavy** — Qwen3-ASR на видеокарте (точность и скорость), **light** — Whisper small на процессоре (когда видеокарта занята игрой или её просто нет).

## Проблема

Готовые голосовые ассистенты — это чужой сервер и чужая модель: не видно, где и как обрабатывается голос, и нельзя ничего подстроить под себя (например, поправить, что модель систематически путает «Notion» с абракадаброй). Здесь весь конвейер — от записи звука до текста — свой и локальный, кроме финального шага «спросить ИИ», который явно вынесен в отдельный необязательный эндпоинт.

## Архитектура

```
Браузер (запись голоса, MediaRecorder)
        │  webm-аудио
        ▼
Flask-приложение в Docker (app.py)
        │
        ├── ffmpeg → конвертация в WAV 16kHz mono
        │
        ├── heavy: Qwen3-ASR-0.6B (GPU, torch+CUDA)
        │     или
        │   light: faster-whisper small (CPU, int8)
        │
        ├── очистка текста (снятие точки в конце, нормализация терминов:
        │   "гитхаб"→"GitHub", "докер"→"Docker" и т.п. через regex-словарь)
        │
        └── /chat → Google Gemini API (текстовый ответ, опционально)
```

`heavy` и `light` — два независимых Docker-образа с одинаковым HTTP-контрактом (`/transcribe`, `/chat`), поэтому фронтенд (`templates/`, `static/`) общий и не знает, какой движок сейчас поднят.

## Технологии

Flask, Docker + Docker Compose (два отдельных compose-файла на один и тот же порт — поднят может быть только один движок за раз), PyTorch + CUDA — инференс Qwen3-ASR-0.6B (Alibaba, открытые веса) на GPU, faster-whisper (CTranslate2) — инференс Whisper small на CPU, ffmpeg — конвертация аудио, Google Gemini API — необязательный текстовый ответ.

## Структура

```
heavy/app.py, heavy/Dockerfile        — движок на GPU (Qwen3-ASR)
light/app.py, light/Dockerfile        — движок на CPU (Whisper small)
docker-compose.heavy.yml / .light.yml — поднимают один и тот же порт разными движками
templates/index.html, static/        — общий фронтенд (чат, кнопка микрофона)
.env.example                          — куда положить ключ Gemini
```

## Установка/запуск

1. Установить Docker Desktop (для `heavy` дополнительно нужна видеокарта NVIDIA с включённой поддержкой GPU в Docker).
2. Скопировать `.env.example` в `.env` и вписать бесплатный ключ Gemini с `aistudio.google.com/apikey` — без ключа чат-ответ просто отключается, распознавание речи работает и так.
3. Поднять облегчённый вариант (работает на любом ПК):
   ```
   docker compose -f docker-compose.light.yml up -d --build
   ```
   или вариант на видеокарте (если она есть):
   ```
   docker compose -f docker-compose.heavy.yml up -d --build
   ```
4. Открыть `http://localhost:5451` — нажать на микрофон и сказать что-нибудь.
5. Чтобы переключиться между движками — остановить один compose-файл и поднять другой (порт у них общий, 5451).

## Пример работы

Нажимаешь на микрофон, говоришь фразу — через несколько секунд она появляется в чате уже как текст, без точки на конце и с поправленными техническими терминами. Если вписан ключ Gemini — справа сразу появляется ответ ИИ на сказанное.

## Дальнейшие улучшения

- Автоматический выбор движка по наличию GPU вместо ручного переключения compose-файлов.
- Потоковое распознавание прямо во время речи, а не только после завершения записи.

## Куда можно добавить ML

Это и есть ML-проект — весь смысл в развёртывании и сравнении двух моделей распознавания речи (0.6B параметров на GPU против классического Whisper на CPU) на одной и той же задаче. Дальше стоит:
- Замерить и сравнить модели не на глаз, а метрикой (WER — word error rate) на одном и том же наборе своих фраз, вместо словарной подмены отдельных терминов после факта.
- Дообучить (fine-tune) модель на своём голосе и характерных для меня терминах (имена программ, английские слова) — вместо regex-заплаток `TERM_CORRECTIONS` в коде.
- Добавить определение говорящего/шумоподавление перед распознаванием, если писать голос не с близкого микрофона.
